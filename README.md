# Signature Detector Batch v13.1
BUILD 13.1 · 2026-08-12

## 사용자 목표 재정의

출력은 성능점검기록부 전체가 아니라 아래 한 영역뿐입니다.

- 아직 숫자가 작성되지 않은 `년 / 월 / 일`
- `매수인`
- `서명` 또는 `(인)`
- 실제 서명을 쓸 공간
- 주변 약 40px margin

## v12 이하의 실패 원인

이전 구조는 전체 페이지 OCR 결과에서 키워드 좌표를 섞어 사용했습니다.
가로로 두 페이지가 붙은 스캔에서는 왼쪽 논리 페이지의 날짜와
오른쪽 논리 페이지의 매수인/서명을 하나의 후보로 합칠 수 있었습니다.
또 JPG/PNG도 전체 이미지를 반복 OCR하여 느렸습니다.

## v13 구조

### 1. 논리 페이지 먼저 분리
가로 비율이 넓은 문서는:
- 오른쪽 논리 페이지
- 왼쪽 논리 페이지

로 먼저 분리합니다.

### 2. 하단 ROI부터 검색
각 논리 페이지에서:
1. 하단 50%
2. 하단을 포함한 73%
3. 전체 논리 페이지

순으로 확인합니다.

사용자가 제공한 대표 샘플 5종을 시각적으로 재점검한 결과,
모두 `오른쪽 논리 페이지 하단 50%` 후보 안에 실제 매수인 서명란이 포함됩니다.
이 위치는 하드코딩 정답이 아니라 검색 우선순위이며,
실패하면 다른 논리 영역까지 계속 탐색합니다.

### 3. PDF 텍스트 레이어 우선
텍스트 PDF라면 OCR 없이 PDF.js text content 좌표를 먼저 사용합니다.

### 4. 스캔 PDF / JPG / PNG
전체 이미지를 반복 OCR하지 않습니다.
작은 ROI를 1450px 정도로 확대하여 `kor` OCR 한 번만 실행하고,
성공하면 즉시 종료합니다.

실패 때만 adaptive threshold + sparse OCR로 두 번째 pass를 실행합니다.

### 5. 서명영역 판정
강한 조건:
- 숫자가 없는 `년 → 월 → 일`
- 근처 `매수인`
- 근처 `서명 / 서명 또는 인 / 인`

보조 조건:
- 위쪽 `확인 / 확인합니다 / 본인은 / 사실`

`확인합니다`는 필수조건이 아닙니다.

OCR이 날짜 한 글자를 놓치더라도
`매수인 + 서명 + 확인 문맥`이 강하면 fallback 후보를 허용합니다.

### 6. 결과
최종 UI에는 OCR 원문이나 전체 페이지를 표시하지 않습니다.
탐지한 작성 영역만 약 40px margin과 함께 원본 품질로 크게 표시합니다.


## v13.1 자체 점검 추가

- PDF.js ROI offset-render 방식을 제거하고 페이지를 1회 정상 렌더한 뒤 crop하도록 변경.
- 한 페이지의 여러 검색 ROI는 같은 page canvas를 재사용.
- `매 수 인`, `서명 또는 인`처럼 OCR 결과가 여러 token으로 갈라지는 경우
  같은 줄의 2~5 token n-gram을 자동 조합하여 다시 판정.
- TypeScript 소스는 외부 라이브러리 declaration stub을 사용한 `tsc --noEmit` 구문/타입 점검을 통과.
