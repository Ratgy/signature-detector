# FAST v2

- 저해상도 text-only OCR로 페이지/방향을 먼저 선택
- 선택된 한 페이지만 blocks 정밀 OCR
- `년·월·일` + `서명/인/매수인`이 함께 있는 작은 영역만 후보 인정
- 모바일 속도 측정 표시 추가

# 모바일 업로드용 Flat 구조

이 폴더의 파일들은 **모두 저장소 루트에 그대로 업로드**하면 됩니다. `src/` 폴더를 만들 필요가 없습니다.

# 성능점검기록부 서명영역 탐지 프로토타입

서로 다른 스캔 PDF에서 **연월일 / 매수인 / 서명 / (인)** 같은 인쇄 라벨을 브라우저 OCR로 찾고,
서명 가능성이 높은 영역을 후보 1~3개로 제시하는 기술 검증용 웹입니다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 Vite가 표시하는 로컬 주소를 엽니다.

> 첫 OCR 실행 시 Tesseract.js가 `kor+eng` 학습 데이터를 다운로드합니다.
> 유료 API 호출은 없지만 최초 실행에는 인터넷 연결이 필요할 수 있습니다.
> 브라우저 캐시 상태에 따라 이후 재사용됩니다.

## 구현한 것

- 실제 PDF 업로드
- PDF.js 페이지 렌더
- 고해상도 OCR용 렌더
- 회색조 + 보수적 대비 강화
- Tesseract.js `kor+eng` OCR
- word bounding box 추출
- `매수인`, `연월일`, `서명`, `(인)` 등 keyword fuzzy matching
- 같은 줄의 분리 OCR(`매 수 인`)을 위한 n-gram 결합
- 키워드 근접도 / 같은 행 / 문서 하단 위치 / OCR confidence 점수화
- 후보 최대 3개
- 0° → 90° → 270° → 180° 자동 회전 fallback
- 후보 영역 Crop 확대
- 원본 페이지에서 후보 위치 표시
- 정확함 / 일부 포함 / 틀림 / 탐지 실패 평가
- localStorage 기반 Exact / Usable 간이 통계
- DEV 모드에서 candidate score / 좌표 / OCR token 확인

## 탐지 로직

이 프로토타입은 AI 의미 추론을 하지 않습니다.

1. PDF를 1.8~3.1배 정도로 렌더합니다.
2. OCR로 단어와 위치를 구합니다.
3. 키워드 및 OCR 오타와 유사한 문자열을 찾습니다.
4. 인접 키워드를 cluster로 묶습니다.
5. 다음 요소에 점수를 줍니다.
   - 매수인/연월일/서명/(인) 등 키워드
   - 키워드 간 거리
   - 동일 행 또는 인접 행
   - 페이지 하단 위치
   - OCR confidence
6. 가장 높은 cluster를 서명 후보로 선택하고 주변 작성 공간까지 확장합니다.

## 중요한 현재 한계

- 완전히 새로운 양식에서 OCR이 라벨 자체를 놓치면 탐지할 수 없습니다.
- `인`은 매우 흔한 글자라 낮은 가중치만 사용합니다.
- 표 선(line) 검출은 아직 넣지 않았습니다. OCR-only 성공률이 부족하면 OpenCV.js 기반 표/빈칸 검출을 다음 실험으로 권장합니다.
- 스캔의 원근 왜곡(perspective distortion) 자동 보정은 하지 않습니다.
- 후보 Crop의 표시 계층은 고해상도 OCR 렌더 이미지를 CSS clipping으로 보여줍니다. 탐지 좌표 자체는 normalized 좌표입니다.
- 현재 목표는 전자서명 완성이 아니라 **서명 영역 자동 탐지 성공률 측정**입니다.

## 추천 테스트 방법

서로 다른 상사/양식 PDF를 최소 20~30개 넣고 각 결과를 아래 중 하나로 평가하세요.

- 정확함: 서명해야 할 영역을 충분히 정확하게 포함
- 일부 포함: 약간 벗어났지만 확대 후 바로 수정 가능한 수준
- 틀림: 잘못된 곳
- 탐지 실패: 후보가 만들어지지 않음

**Usable Detection Rate = (정확함 + 일부 포함) / 전체**

이 수치가 실제 UX 적용 가능성을 판단하는 핵심 지표입니다.


## 모바일에서 바로 테스트

PC와 휴대폰을 같은 Wi-Fi에 연결한 뒤:

```bash
npm install
npm run dev:mobile
```

터미널에 표시되는 `Network` 주소(예: `http://192.168.0.12:5173`)를 휴대폰 Chrome/Safari에서 엽니다.

이 방식은 모바일에서도 실제 웹 페이지로 실행되며, 휴대폰의 파일 선택창에서 PDF를 선택해 OCR 탐지를 테스트할 수 있습니다.

### 외부에서도 접속하려면

프로젝트를 Vercel / Netlify / Cloudflare Pages 같은 정적 웹 호스팅에 배포하면 됩니다.

빌드 명령:

```bash
npm run build
```

배포 폴더:

```text
dist
```

PDF 파일과 OCR 결과는 서버로 업로드하지 않고 브라우저 메모리에서 처리하도록 설계되어 있습니다.

### 모바일 성능 참고

OCR은 휴대폰 CPU/WASM에서 직접 실행되므로 데스크톱보다 느릴 수 있습니다.
특히 고해상도·다페이지 PDF는 메모리 사용량이 커질 수 있으므로 실제 모바일 테스트 결과를 보고 OCR 렌더 스케일과 페이지 처리 방식을 조정하는 것이 좋습니다.
